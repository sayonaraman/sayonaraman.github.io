Запросы, CRUD и статус-коды: гид для вайбкодеров 🚀

📅 4 ноября 2025 • ⏱️ 5 мин

Привет! Если ты только начинаешь свой путь в программировании и хочешь автоматизировать браузеры или приложения, тебе нужно понимать, как они общаются с серверами. Давай разберем это на простых примерах, без заумных терминов.

Что такое запросы (requests)?

Представь, что ты в ресторане. Ты — это браузер или приложение, а официант — это сервер. Когда ты хочешь заказать еду, ты делаешь запрос официанту. Он идет на кухню и приносит тебе ответ (твое блюдо или информацию, что блюда нет).

В мире программирования запросы работают точно так же: - Ты (браузер) отправляешь запрос серверу: "Дай мне главную страницу сайта" - Сервер отвечает: "Держи HTML-код страницы" или "Ошибка, страницы нет"

Основные типы запросов

Есть несколько типов запросов, но для начала тебе нужны четыре главных. Они называются методы HTTP и составляют аббревиатуру CRUD.

CRUD — четыре кита веб-разработки

CRUD расшифровывается как Create, Read, Update, Delete (Создать, Прочитать, Обновить, Удалить). Это четыре базовые операции, которые можно делать с данными.

1. POST — Create (Создать)

Это когда ты создаешь что-то новое.

Пример из жизни: - Регистрируешься на сайте — отправляется POST-запрос с твоими данными - Публикуешь пост в соцсети — POST-запрос - Добавляешь товар в корзину — POST-запрос

Что происходит: Браузер говорит серверу: "Вот тебе новые данные, сохрани их!"

2. GET — Read (Прочитать)

Это когда ты просто получаешь информацию, ничего не меняя.

Пример из жизни: - Открываешь сайт — GET-запрос за HTML-страницей - Смотришь список товаров в магазине — GET-запрос - Загружаешь картинку — GET-запрос

Что происходит: Браузер говорит серверу: "Дай мне вот эти данные, просто посмотреть"

3. PUT/PATCH — Update (Обновить)

Это когда ты изменяешь уже существующие данные.

Пример из жизни: - Редактируешь свой профиль — PUT/PATCH-запрос - Меняешь количество товара в корзине — PUT/PATCH-запрос - Обновляешь пост — PUT/PATCH-запрос

Что происходит: Браузер говорит серверу: "Эти данные устарели, замени их на новые"

Разница между PUT и PATCH: PUT заменяет всю запись целиком, PATCH — только конкретные поля. Но для вайбкодинга это детали, главное — понимать, что это обновление.

4. DELETE — Delete (Удалить)

Тут все понятно — удаление данных.

Пример из жизни: - Удаляешь свой комментарий — DELETE-запрос - Убираешь товар из корзины — DELETE-запрос - Удаляешь аккаунт — DELETE-запрос

Что происходит: Браузер говорит серверу: "Удали эти данные"

Статус-коды — ответы сервера

Когда сервер получает твой запрос, он всегда отвечает статус-кодом — это число, которое объясняет, что произошло. Это как эмодзи официанта в ответ на твой заказ 😊 или 😞

Статус-коды состоят из трех цифр, и первая цифра показывает категорию ответа:

2xx — Успех ✅

Все прошло отлично!

  • 200 OK — "Все супер, вот твои данные"
  • 201 Created — "Создано! Твой новый пост/аккаунт/товар сохранен"
  • 204 No Content — "Готово, но данных для показа нет" (например, после удаления)

3xx — Перенаправление 🔄

Тебе нужно пойти в другое место.

  • 301 Moved Permanently — "Эта страница переехала навсегда, иди по новому адресу"
  • 302 Found — "Временно иди по другому адресу"
  • 304 Not Modified — "У тебя уже есть актуальная версия, ничего не изменилось"

4xx — Ошибка клиента ❌

Ты (браузер) что-то сделал не так.

  • 400 Bad Request — "Твой запрос какой-то кривой, не понимаю"
  • 401 Unauthorized — "Кто ты вообще? Войди в систему!"
  • 403 Forbidden — "Я знаю кто ты, но тебе сюда нельзя"
  • 404 Not Found — "Того, что ты ищешь, не существует"
  • 429 Too Many Requests — "Слишком много запросов, притормози!"

5xx — Ошибка сервера 💥

Проблема на стороне сервера, не у тебя.

  • 500 Internal Server Error — "У меня что-то сломалось, сорян"
  • 502 Bad Gateway — "Сервер-посредник получил плохой ответ"
  • 503 Service Unavailable — "Сервер перегружен или на техобслуживании"

Консольные логи — твой рентген браузера

Когда ты автоматизируешь браузер, тебе нужно видеть, что происходит "под капотом". Для этого есть консоль разработчика.

Как открыть консоль:

В любом браузере: - Нажми F12 или - Правой кнопкой мыши → "Просмотреть код" / "Inspect" - Или Ctrl+Shift+I (Windows/Linux) / Cmd+Option+I (Mac)

Что смотреть:

  1. Вкладка Console — здесь выводятся ошибки JavaScript, логи, предупреждения
  2. Вкладка Network — здесь ВСЕ запросы, которые делает страница

Во вкладке Network ты увидишь: - Какие запросы отправляются (GET, POST и т.д.) - К каким адресам (URL) - Какие статус-коды приходят (200, 404, 500...) - Какие данные отправляются и приходят

Совет для вайбкодинга: Открой сайт, который хочешь автоматизировать, включи вкладку Network и начни кликать по сайту. Ты увидишь, какие запросы отправляются при каждом действии. Это карта сокровищ для автоматизации!

HAR-файлы — запись всего трафика

HAR (HTTP Archive) — это файл, в котором записаны ВСЕ запросы и ответы между браузером и сервером. Это как видеозапись всех действий.

Как получить HAR-файл:

  1. Открой DevTools (F12)
  2. Перейди во вкладку Network
  3. Обнови страницу или сделай действия, которые хочешь записать
  4. Правой кнопкой мыши по списку запросов → "Save all as HAR with content" или "Export HAR"

Зачем это нужно для вайбкодинга?

HAR-файл можно передать ИИ-ассистенту (например, ChatGPT, Claude, Cursor), и он поймет: - Какие запросы делает сайт - В каком порядке - Какие данные отправляются - Какие токены авторизации используются - Какие cookies нужны

ИИ увидит точный POST-запрос с нужными заголовками и телом запроса, и сгенерирует код.

Бонус: инспектирование запросов

Во вкладке Network, кликни на любой запрос — ты увидишь: - Headers — заголовки (там может быть Authorization, Cookie, Content-Type) - Payload — данные, которые ты отправил - Response — что сервер ответил - Preview — красивый вид ответа

Это золотая информация для создания скриптов автоматизации!

Итого: твой чек-лист вайбкодера

  1. Запросы — это как ты общаешься с сервером (заказ в ресторане)
  2. CRUD — четыре основных действия: создать (POST), прочитать (GET), обновить (PUT/PATCH), удалить (DELETE)
  3. Статус-коды — ответы сервера: 2xx (успех), 3xx (редирект), 4xx (ты ошибся), 5xx (сервер ошибся)
  4. Console (F12) — твой рентген браузера, смотри ошибки и логи
  5. Network (F12) — видишь все запросы в реальном времени
  6. HAR-файлы — экспорт всех запросов, которые можешь скормить ИИ для создания скриптов

Открывай DevTools, смотри, какие запросы делает нужный сайт, и автоматизируй всё, что душе угодно. Удачи! 🚀
